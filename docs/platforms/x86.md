# x86 platform

## Build a live ISO image with linux-firmware included

First, obtain the linux-firmware files in a directory. This can be
done in one of the following ways:

- Clone the linux-firmware repository from
  [upstream](https://gitlab.com/kernel-firmware/linux-firmware) and
  run its `copy-firmware.sh` script with an output directory
  specified. Note that using the files from the repository directly
  will result in missing symbolic links.
- Use the files in `/lib/firmware` from a Linux OS installation on the
  target device.

Then, pack the directory containing linux-firmware files into an image
named `linux-firmware.img`:

```
mkfs.erofs -zlzma linux-firmware.img <path to the directory containing linux-firmware files>
```

Finally, build the live ISO image with the following environment
variable set:

```
TARGET_LINUX_FIRMWARE_IMAGE=<absolute path to the linux-firmware.img which we have made>
```

## Firmware types

The live ISO image boots on all of the following:

| Firmware | Boot file in the ISO |
|----------|----------------------|
| 64-bit UEFI | `/efi/boot/bootx64.efi` |
| 32-bit UEFI on a 64-bit CPU | `/efi/boot/bootia32.efi` |
| Legacy BIOS | `/boot/grub/i386-pc/eltorito.img` |

The 32-bit UEFI entry is for machines such as some Intel Atom tablets
and early Apple Macs, which have a 64-bit CPU but 32-bit UEFI firmware.
GRUB for `i386-efi` starts the 64-bit kernel in EFI mixed mode, so the
kernel needs `CONFIG_EFI_MIXED=y`, which `Generic_x86_64` enables.

All three come from the GRUB prebuilts in `prebuilts/bootmgr`
(`x86_64-efi`, `i386-efi` and `i386-pc`), and the build fails if the
`i386-efi` or `i386-pc` one is missing. For other boot media, add a
`BOOTIA32.EFI` built from the `i386-efi` prebuilts next to `BOOTX64.EFI`.

## Writing the live ISO image to boot media

The boot media should normally be a DVD-ROM.

Writing it directly to a disk-type boot medium such as a USB drive
will usually result in the init program failing to find the Android
images at boot time.

If you want to use a disk as the boot medium, it is recommended to
copy the content files and set up the boot loader manually, or use an
image-writing tool that performs the necessary conversion to ensure
the correct filesystem can be mounted.
